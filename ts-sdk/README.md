# `@supython/sdk` — TypeScript Client SDK

> **Version:** 0.1.0
> **Target:** Node.js ≥ 18, modern browsers (ES2022)
> **Dependencies:** `@supabase/postgrest-js` (query builder), `@supabase/realtime-js` (WebSocket channels)

---

## 1. Overview

`@supython/sdk` is the official TypeScript client for supython — a Postgres-first backend-as-a-service. It provides a typed, composable interface over the four supython service surfaces:

| Sub-client | Accessor | Protocol | Endpoint root |
|---|---|---|---|
| **Auth** | `client.auth` | HTTP (REST) | `/auth/v1/` |
| **PostgREST** | `client.from()` / `client.rpc()` | HTTP (PostgREST) | `/rest/v1/` |
| **Storage** | `client.storage` | HTTP (multipart) | `/storage/v1/` |
| **Functions** | `client.functions` | HTTP (JSON/raw) | `/functions/` |
| **Realtime** | `client.channel()` | WebSocket (Phoenix Channels) | `ws(s)://<host>/realtime/v1` |

The SDK delegates PostgREST query building and realtime channel management to battle-tested, MIT-licensed upstream packages (`@supabase/postgrest-js` and `@supabase/realtime-js`). Auth, storage, and functions are supython-specific thin wrappers that speak directly to the FastAPI server.

**Design principles:**

- **No ORM.** PostgREST queries map directly to SQL via HTTP. The SDK is a thin transport layer.
- **`{ data, error }` envelope.** Every operation returns a `SupythonResponse<T>` — never throws for expected failures.
- **No `service_role` in the browser.** The constructor rejects a `serviceRoleKey` combined with browser-persistent storage backends.
- **Mirrors supabase-js API shape** where semantics match, so migration is frictionless.

## 3. Creating a Client

### 3.1 `createClient<Database>(url, options?)`

```typescript
const supython = createClient<Database>('http://localhost:8000', {
  anonKey: 'eyJhbGciOi...',        // optional public anon key (sent as `apikey` header)
  schema: 'public',                 // default PostgREST schema (default: 'public')
  globalHeaders: {                  // extra headers attached to every request
    'X-Client-Version': '1.0.0',
  },
  auth: {
    storage: new MemoryAuthStorage(),  // session persistence backend (see §9)
    autoRefresh: true,                 // auto-refresh access token on 401 (default: true)
    persistSession: true,              // persist session to storage (default: true)
  },
  serviceRoleKey: undefined,       // server-side admin JWT — never set in browser code
});
```

All options are optional. The only required argument is `url` — the base URL of your supython service.

The `Database` generic is the type generated by `supython gen types --lang ts` (see §11). When omitted, `from()` and `rpc()` fall back to untyped `any` returns.

### 3.2 `SupythonClient` surface

| Property / method | Type | Description |
|---|---|---|
| `client.auth` | `AuthClient` | Auth methods: sign-up, sign-in, sign-out, refresh, user lookup, state subscriptions |
| `client.storage` | `StorageClient` | Bucket management and object CRUD |
| `client.functions` | `FunctionsClient` | Edge function invocation |
| `client.from(table)` | `PostgrestQueryBuilder` | Build PostgREST queries with chainable filters |
| `client.rpc(fn, params?)` | `PostgrestFilterBuilder` | Call a Postgres function via PostgREST |
| `client.channel(topic)` | `RealtimeChannel` | Open a realtime WebSocket channel |
| `client.removeChannel(channel)` | `Promise<'ok' \| 'timed out' \| 'error'>` | Tear down a channel |
| `client.onAuthStateChange(cb)` | `() => void` | Subscribe to auth state changes; returns unsubscribe |

## 4. Auth

The `AuthClient` (`client.auth`) handles the full JWT lifecycle: sign-up, sign-in, refresh, sign-out, and user lookup. v0.1.0 ships email+password auth only. OTP, magic link, OAuth, and password recovery are deferred to v0.2.0 (the server endpoints already exist — the SDK does not wrap them yet).

### 4.1 `signUp(email, password)`

```typescript
const { data, error } = await client.auth.signUp('user@example.com', 'secure-pass');
if (error) {
  console.error(error.code, error.message);  // e.g. 'user_exists', 409
  return;
}
// data: Session { access_token, refresh_token, expires_in, user }
```

- **Endpoint:** `POST /auth/v1/signup`
- **Behaviour:** On success, the session is adopted internally — `_accessToken` / `_refreshToken` are set, the session is persisted to the configured storage backend, and `SIGNED_IN` is emitted to all subscribers. On error, no session mutation or event occurs.
- **Errors:** `409 user_exists`, `400 weak_password`, `400 invalid_email`, `429 rate_limited`.

### 4.2 `signInWithPassword(email, password)`

```typescript
const { data, error } = await client.auth.signInWithPassword('user@example.com', 'secure-pass');
```

- **Endpoint:** `POST /auth/v1/token`
- **Behaviour:** Identical session-adoption flow as `signUp`.
- **Errors:** `401 invalid_credentials`, `429 rate_limited`.

### 4.3 `signOut()`

```typescript
const { error } = await client.auth.signOut();
```

- **Endpoint:** `POST /auth/v1/logout`
- **Behaviour:** The local session is unconditionally cleared and `SIGNED_OUT` is emitted *before* checking the server response. The server-side revocation is fire-and-forget: even if the server returns an error, the caller is signed out locally. If no refresh token is present (e.g., already signed out), the call is a no-op.
- **Errors:** Server errors are returned but do not prevent local sign-out.

### 4.4 `refreshSession()`

```typescript
const { data, error } = await client.auth.refreshSession();
```

- **Endpoint:** `POST /auth/v1/refresh`
- **Behaviour:** On success, tokens are rotated (the old refresh token is revoked by the server), state is updated, and `TOKEN_REFRESHED` is emitted. On 4xx (reuse detection), all state is cleared and `SIGNED_OUT` is emitted. If no refresh token is available, `SIGNED_OUT` is emitted and an error with `code: 'no_session'` is returned.
- **Errors:** `401 invalid_refresh` (reuse detection), `code: 'no_session'` (no token available).

### 4.5 `getUser()`

```typescript
const { data: user, error } = await client.auth.getUser();
// user: User { id: string; email: string; created_at: string } | null
```

- **Endpoint:** `GET /auth/v1/user`
- **Behaviour:** Requires an access token. If no token is present, returns `{ data: null, error: { code: 'no_session', ... } }` without making an HTTP call. If the fetched user differs from the currently cached user, `USER_UPDATED` is emitted.
- **Errors:** `401 invalid_token`, `code: 'no_session'`.

### 4.6 `getSession()`

```typescript
const session = client.auth.getSession();
// session: Session | null
```

Synchronous snapshot of the current in-memory session state. Returns `null` when there is no active session. This is an **explicit deviation** from supabase-js (which returns a `Promise`). The synchronous shape matches the Python SDK.

**`Session` shape:**

```typescript
interface Session {
  access_token: string;
  refresh_token: string;
  expires_in: number;   // 0 from getSession(); real value only from signUp/signInWithPassword/refreshSession
  user: User | null;
}

interface User {
  id: string;
  email: string;
  created_at: string;   // ISO-8601 UTC
}
```

The fields use `snake_case` to preserve wire compatibility with the server and the Python SDK.

### 4.7 `onAuthStateChange(callback)`

```typescript
const unsubscribe = client.auth.onAuthStateChange((event, session) => {
  console.log(event);   // 'SIGNED_IN' | 'SIGNED_OUT' | 'TOKEN_REFRESHED' | 'USER_UPDATED'
  console.log(session); // Session | null
});

// Later:
unsubscribe();
```

- Returns an unsubscribe function. This **deviates** from supabase-js (which returns a `{ data: { subscription } }` object). Kept simple for parity with the Python SDK.
- Callbacks fire synchronously during the emit cycle, after state has been mutated and persisted.
- Listener errors are caught and swallowed — one bad listener does not prevent others from firing.

### 4.8 Auto-refresh on 401

When `autoRefresh` is enabled (default), PostgREST requests returning 401 automatically trigger a single `refreshSession()` call. If successful, the original request is retried with the new access token. If the refresh fails (reuse detection), `SIGNED_OUT` is emitted and the original 401 bubbles to the caller.

Concurrent 401s are coalesced into a single refresh via an in-flight `Promise` — N parallel requests that all receive 401 share one refresh round-trip.

**Known limitation (v0.1.0):** Auto-refresh on 401 applies to PostgREST requests only (`from()` and `rpc()`). Storage and Functions clients use plain `fetch` and do not retry after 401. Callers must check `error.status` and invoke `client.auth.refreshSession()` themselves.

## 5. PostgREST Queries

The SDK delegates PostgREST query building to `@supabase/postgrest-js`. This means all filter operators, ordering, pagination, UPSERT, embedded resources, and column-level type inference are available without any SDK code.

### 5.1 `from(table)`

```typescript
const { data, error } = await client
  .from('todos')
  .select('id, title, completed')
  .eq('user_id', uid)
  .order('created_at', { ascending: false })
  .limit(10);
```

A fresh `PostgrestClient` is constructed per-call (no caching), with a custom `fetch` wrapper that:
1. Reads current headers (`apikey` + `Authorization: Bearer <token>`) per request, so token rotations are immediately visible.
2. Intercepts 401 responses for auto-refresh (when `autoRefresh: true`).

**Filter operators** — all inherited from `@supabase/postgrest-js`:
`.eq()`, `.neq()`, `.gt()`, `.gte()`, `.lt()`, `.lte()`, `.like()`, `.ilike()`, `.is()`, `.in()`, `.contains()`, `.containedBy()`, `.rangeLt()`, `.rangeGt()`, `.rangeGte()`, `.rangeLte()`, `.overlaps()`, `.textSearch()`, `.not()`, `.or()`, `.filter()`, `.match()`

**Modifiers:** `.order()`, `.limit()`, `.range()`, `.single()`, `.maybeSingle()`, `.select()`, `.insert()`, `.upsert()`, `.update()`, `.delete()`, `.csv()`.

### 5.2 `rpc(fn, params?)`

```typescript
const { data } = await client.rpc<number>('increment_counter', { by: 1 });
```

Calls a Postgres function via `POST /rest/v1/rpc/{fn}`. Same header and auto-refresh behaviour as `from()`.

### 5.3 Type-safe queries with generated `Database`

When you pass a `Database` type generated by `supython gen types --lang ts` (see §11), query results are column-level typed:

```typescript
import type { Database } from './types.ts';

const client = createClient<Database>(url, { anonKey: '...' });

const { data } = await client
  .from('todos')
  .select('id, title, completed');
// data: { id: string; title: string; completed: boolean }[] | null

const { data } = await client
  .from('todos')
  .select('*, users(name)');
// data: ({ id: string; ... } & { users: { name: string } | null })[] | null
```

The `TableName<Database>` utility type is exported so you can build typed helpers:

```typescript
import type { TableName } from '@supython/sdk';

async function getRows<DB, T extends TableName<DB>>(
  client: SupythonClient<DB>,
  table: T,
): Promise<DB['public']['Tables'][T]['Row'][]> {
  const { data } = await client.from(table).select('*');
  return data ?? [];
}
```

## 6. Storage

`StorageClient` (`client.storage`) manages buckets and produces `StorageBucket` handles for object operations. Headers (`apikey` + `Authorization`) are read from the parent client's `_getHeaders()` callback per-request.

### 6.1 Bucket management

```typescript
// Create a bucket
const { data: bucket, error } = await client.storage.createBucket('avatars', {
  public: false,
  file_size_limit: 5 * 1024 * 1024,   // 5 MB
  allowed_mime_types: ['image/png', 'image/jpeg'],
});

// List all buckets
const { data: buckets } = await client.storage.listBuckets();

// Get a single bucket
const { data: bucket } = await client.storage.getBucket('avatars');

// Delete a bucket
const { error } = await client.storage.deleteBucket('avatars');
```

### 6.2 Working with a bucket: `from(bucketName)`

```typescript
const bucket = client.storage.from('avatars');
// Returns a StorageBucket handle — synchronous, no HTTP call.
```

### 6.3 Object operations

#### `upload(path, body, options?)`

```typescript
// Upload a File/Blob
const file = new File(['...'], 'avatar.png', { type: 'image/png' });
const { data: obj, error } = await bucket.upload('profile/avatar.png', file);

// Upload raw bytes
const bytes = new Uint8Array([1, 2, 3, 4, 5]);
const { data: obj } = await bucket.upload('data.bin', bytes, {
  contentType: 'application/octet-stream',
});
```

- **Endpoint:** `POST /storage/v1/object/{bucket}/{path}`
- **Body:** `multipart/form-data` with field name `file`. `Blob`/`File` instances are appended directly; other types are wrapped in a `Blob`.
- **Errors:** `404 bucket_not_found`, `413 file_too_large`, `415 mime_not_allowed`.

#### `download(path)`

```typescript
const { data: blob, error } = await bucket.download('profile/avatar.png');
if (blob) {
  const buffer = await blob.arrayBuffer();
}
```

- **Endpoint:** `GET /storage/v1/object/{bucket}/{path}`
- **Returns:** `SupythonResponse<Blob>` — the body is parsed as a `Blob` (not JSON).

#### `remove(path)`

```typescript
const { error } = await bucket.remove('profile/avatar.png');
```

- **Endpoint:** `DELETE /storage/v1/object/{bucket}/{path}`
- Single path only. Batch removal is not yet supported (server endpoint pending).

#### `createSignedUrl(path, options?)`

```typescript
const { data: signed, error } = await bucket.createSignedUrl('private/report.pdf', {
  expiresIn: 3600,  // seconds; omit for server default
});
// signed.signed_url: string  (time-limited download URL)
// signed.expires_at: string  (ISO-8601 UTC)
// signed.expires_in: number  (seconds)
```

- **Endpoint:** `POST /storage/v1/object/sign/{bucket}/{path}`

#### `getPublicUrl(path)`

```typescript
const url = bucket.getPublicUrl('banner.jpg');
// Returns: "http://localhost:8000/storage/v1/object/public/avatars/banner.jpg"
```

Synchronous — no HTTP call. Does not verify that the bucket is actually public; callers must ensure the bucket configuration matches their use case.

### 6.4 Storage types

```typescript

}

interface StorageObject {
  id: string;
  bucket_id: string;
  bucket: string;

  mime_type: string | null;

  created_at: string;
```

## 7. Edge Functions

`FunctionsClient` (`client.functions`) invokes filesystem-loaded supython functions over HTTP. Headers (`apikey` + `Authorization`) are attached per-request via the shared `_getHeaders()` callback.

### 7.1 `invoke<T>(name, options?)`

```typescript
// JSON body (default POST)
const { data, error } = await client.functions.invoke<{ msg: string }>('hello', {
  body: { name: 'World' },
});
// data.msg === 'hello, World'

// Custom method
await client.functions.invoke('webhook', { method: 'PUT', body: payload });

// FormData body
const form = new FormData();
form.append('file', blob);
await client.functions.invoke('upload-handler', { body: form });

// Blob / ArrayBuffer / string — pass through unchanged
await client.functions.invoke('binary', { body: new Uint8Array([1, 2, 3]) });
```

- **Endpoint:** `POST /functions/{name}` (default; overridable via `options.method`)
- **`name`** may contain slashes (e.g. `payments/webhook`) — passed through verbatim.
- **Body handling:**
  - `FormData`: passed through; `Content-Type` is dropped so the runtime sets the multipart boundary.
  - `Blob` / `ArrayBuffer` / `string`: passed through; caller controls `Content-Type` via `options.headers`.
  - Plain object or array: serialized to JSON; `Content-Type: application/json` is set automatically unless already provided.
  - `undefined`: no body sent.
- **Response parsing:** JSON responses are deserialized. Binary (`application/octet-stream`) returns `ArrayBuffer`. Text responses return `string`. 204 returns `null`.

### 7.2 `InvokeOptions`

```typescript
interface InvokeOptions {
  body?: Record<string, unknown> | unknown[] | FormData | Blob | ArrayBuffer | string;
  method?: 'GET' | 'POST' | 'PUT' | 'PATCH' | 'DELETE';   // default: 'POST'
  headers?: Record<string, string>;
}
```

## 8. Realtime

The SDK wraps `@supabase/realtime-js` for WebSocket (Phoenix Channels) communication. The realtime client is constructed once at initialization and reauthorized on every auth state change (`setAuth(jwt)` on sign-in / refresh, `setAuth(null)` on sign-out).

### 8.1 `channel(topic)`

```typescript
const channel = client.channel('room:lobby');

channel
  .on('broadcast', { event: 'message' }, (payload) => {
    console.log('received:', payload);
  })
  .subscribe((status) => {
    if (status === 'SUBSCRIBED') {
      channel.send({ type: 'broadcast', event: 'message', payload: { hello: 'world' } });
    }
  });
```

All channel features — presence tracking, broadcast, Postgres CDC (`postgres_changes`) — are inherited from `@supabase/realtime-js`.

### 8.2 `removeChannel(channel)`

```typescript
const result = await client.removeChannel(channel);
// 'ok' | 'timed out' | 'error'
```

Tears down the underlying WebSocket subscription.

## 9. Auth Storage Backends

The SDK supports four strategies for persisting session tokens. The default is auto-detected.

### 9.1 Available backends

| Backend | Class | Target | Best for |
|---|---|---|---|
| **Memory** | `MemoryAuthStorage` | In-memory `Map` | Node.js servers, CLI tools, tests |
| **localStorage** (default browser) | `LocalStorageAuthStorage` | `window.localStorage` | Browser SPAs |
| **Cookie** | `CookieAuthStorage` | `document.cookie` | SSR frameworks (Next.js, Remix) |
| **Custom** | Object implementing `AuthStorageBackend` | User-defined | IndexedDB, React Native `AsyncStorage`, etc. |

### 9.2 `AuthStorageBackend` interface

```typescript
interface AuthStorageBackend {
  getItem(key: string): string | null | Promise<string | null>;
  setItem(key: string, value: string): void | Promise<void>;
  removeItem(key: string): void | Promise<void>;
}
```

Methods may be sync or async — all consumers wrap results in `Promise.resolve()`.

### 9.3 Configuring the backend

```typescript
import { createClient, LocalStorageAuthStorage, CookieAuthStorage, MemoryAuthStorage } from '@supython/sdk';

// Explicit localStorage (SPA)
const client = createClient(url, {
  anonKey: '...',
  auth: { storage: new LocalStorageAuthStorage() },
});

// Cookie backend (SSR)
const client = createClient(url, {
  anonKey: '...',
  auth: {
    storage: new CookieAuthStorage({
      domain: '.example.com',
      secure: true,
      sameSite: 'Lax',
      maxAge: 60 * 60 * 24 * 30,   // 30 days
    }),
  },
});

// Memory (server-side)
const client = createClient(url, {
  anonKey: '...',
  auth: { storage: new MemoryAuthStorage() },
});

// Custom backend
const custom: AuthStorageBackend = {
  getItem: async (key) => myDb.get(key),
  setItem: async (key, value) => myDb.set(key, value),
  removeItem: async (key) => myDb.delete(key),
};
```

### 9.4 Default detection

When no `auth.storage` is specified:
- **Browser** (where `window.localStorage` is usable): `LocalStorageAuthStorage`
- **Node.js** / environments without `localStorage`: `MemoryAuthStorage`

The detection includes a Safari Private Mode probe — if `localStorage` is defined but throws on `setItem`, the SDK falls back to `MemoryAuthStorage`.

### 9.5 `isBrowserStorage(backend)`

```typescript
import { isBrowserStorage } from '@supython/sdk';

isBrowserStorage(new LocalStorageAuthStorage());   // true
isBrowserStorage(new CookieAuthStorage());         // true
isBrowserStorage(new MemoryAuthStorage());         // false
isBrowserStorage(myCustomBackend);                 // false
```

Used internally by the `serviceRoleKey` safety guard.

### 9.6 Persisted payload

Sessions are serialized as JSON under the key `supython-session`:

```json
{
  "access_token": "...",
  "refresh_token": "...",
  "expires_at": 1717000000000
}
```

`expires_at` is a Unix timestamp in milliseconds (wall-clock, computed as `Date.now() + expires_in * 1000` at sign-in/refresh time).

## 10. Error Handling

### 10.1 `SupythonResponse<T>`

Every async operation returns this shape — the SDK never throws for expected failures:

```typescript
interface SupythonResponse<T> {
  data: T | null;
  error: AuthError | StorageError | FunctionsError | PostgrestError | null;
}
```

Network-level failures (connection refused, DNS failure, timeout) are caught and converted to typed error objects with `code: 'network_error'` and `status: 0`.

### 10.2 Error types

```typescript
interface AuthError {
  code: string;      // e.g. 'user_exists', 'invalid_credentials', 'no_session'
  message: string;   // Human-readable description
  status: number;    // HTTP status code (0 for network errors)
}

interface StorageError {
  code: string;      // e.g. 'bucket_not_found', 'file_too_large', 'object_not_found'
  message: string;
  status: number;
}

interface FunctionsError {
  code: string;      // e.g. 'function_not_found', 'method_not_allowed'
  message: string;
  status: number;
}
```

`PostgrestError` is re-exported from `@supabase/postgrest-js` and carries the standard PostgREST error shape (`code`, `details`, `hint`, `message`).

### 10.3 Error handling patterns

```typescript
// Pattern 1: Guard clause
const { data, error } = await client.auth.signUp(email, password);
if (error) {
  if (error.status === 409) { /* user exists */ }
  if (error.status === 0)   { /* network error */ }
  return;
}
// data is safe to use

// Pattern 2: Destructure with null checks
const { data: user } = await client.auth.getUser();
if (!user) { /* not authenticated or error */ }
```

## 11. Type Generation: `supython gen types --lang ts`

The `@supython/sdk` package does **not** bundle application-specific types. Users generate a TypeScript `Database` interface from their Postgres schema using the supython CLI:

```bash
supython gen types --lang ts --schema public --out ./src/types.ts
```

This produces a `Database` interface compatible with `@supabase/postgrest-js`'s generic conventions:

```typescript
// Generated by supython gen types --lang ts. Do not edit.

export interface Database {
  public: {
    Tables: {
      todos: {
        Row: {
          id: string;
          title: string;
          completed: boolean;
          user_id: string;
          created_at: string;
        };
        Insert: {
          id?: string;
          title: string;
          completed?: boolean;
          user_id?: string;
          created_at?: string;
        };
        Update: {
          id?: string;
          title?: string;
          completed?: boolean;
          user_id?: string;
          created_at?: string;
        };
        Relationships: [{
          foreignKeyName: "todos_user_id_fkey";
          columns: ["user_id"];
          referencedRelation: "users";
          referencedColumns: ["id"];
        }];
      };
    };
    Views: { /* same Row/Insert/Update shape */ };
    Functions: { /* RPC return types — deferred to future version */ };
    Enums: {
      todo_status: "pending" | "done" | "archived";
    };
  };
}
```

**Postgres-to-TypeScript type mapping:**

| Postgres type | TypeScript type |
|---|---|
| `uuid`, `text`, `varchar`, `bpchar`, `char`, `citext`, `name`, `inet`, `cidr`, `bytea`, `macaddr`, `tsvector`, `tsquery` | `string` |
| `int2`, `int4`, `int8`, `float4`, `float8`, `numeric`, `money` | `number` |
| `bool` | `boolean` |
| `timestamptz`, `timestamp`, `date`, `time`, `timetz`, `interval` | `string` (ISO 8601) |
| `json`, `jsonb` | `Record<string, unknown>` |
| Custom enum | String literal union (`"val1" \| "val2"`) |
| Array types (`text[]`, `int4[]`) | `string[]`, `number[]` |
| Unknown / unmapped | `unknown` |

**Field optionality logic:**

| Variant | Optional when... |
|---|---|
| `Row` | `is_nullable = YES` |
| `Insert` | `is_nullable = YES` OR has a default value |
| `Update` | Always (all fields are optional) |

**Multi-schema mode:**

```bash
supython gen types --lang ts --schema public,auth --out ./src/types.ts
```

Non-public schemas get a schema-name prefix in PascalCase (e.g., `auth.users` → `AuthUsers`).

## 12. Security Considerations

### 12.1 Token storage

- **SPAs:** `LocalStorageAuthStorage` (default in browser) is appropriate for most single-page apps.
- **SSR:** `CookieAuthStorage` provides cookie-based persistence so the server can read the session. Note that cookies set via `document.cookie` are **not** `HttpOnly` — frameworks that require `HttpOnly` must mint the cookie server-side.
- **Server-side:** `MemoryAuthStorage` keeps sessions in process memory only.

### 12.2 `serviceRoleKey` guard

The `serviceRoleKey` option pre-populates the internal access token with a pre-issued `service_role` JWT, bypassing Row-Level Security (RLS). The constructor enforces a safety guard:

```typescript
// Throws: "serviceRoleKey requires anonKey to be set"
createClient(url, { serviceRoleKey: '...' });

// Throws: "serviceRoleKey must not be combined with a browser-persistent auth-storage backend"
createClient(url, {
  anonKey: '...',
  serviceRoleKey: '...',
  auth: { storage: new LocalStorageAuthStorage() },
});

// OK — server-side only
createClient(url, {
  anonKey: '...',
  serviceRoleKey: '...',
  auth: { storage: new MemoryAuthStorage() },
});
```

### 12.3 Token attachment

- `apikey` (anon key) is sent as the `apikey` header, never as an `Authorization` header.
- After authentication, `Authorization: Bearer <access_token>` is automatically attached to every PostgREST, storage, and functions request.
- The SDK never exposes raw tokens in a way the caller could accidentally log — token management is fully internal.

### 12.4 Refresh token rotation

The server implements refresh token reuse detection. When a refresh token is used, the server issues a new refresh token and revokes the old family. If a 401 is received on refresh (reuse detection), the SDK clears all local state and emits `SIGNED_OUT`.

## 13. Versioning & Compatibility

The `@supython/sdk` npm package has its own semver, independent of the supython Python server version.

| SDK (`@supython/sdk`) | supython server (Python) |
|---|---|
| `0.1.x` | ≥ 0.7.0 |

A compatibility table is maintained in CI — E2E tests run against the minimum supported server version.

## 14. Relationship to `@supabase/supabase-js`

The SDK mirrors supabase-js's API shape wherever the underlying supython service semantics match:

- `client.from(table)` — same chainable filter grammar, same operators.
- `client.auth.signUp/signInWithPassword/signOut/getSession/onAuthStateChange` — same method names and signature shapes.
- `client.storage.from(bucket).upload/download/remove/getPublicUrl/createSignedUrl` — same model.
- `client.channel(topic)` — same Phoenix Channels primitives.

**Key architectural difference:** supabase-js bundles its PostgREST and realtime clients as internal dependencies of a monolithic package. `@supython/sdk` depends on `@supabase/postgrest-js` and `@supabase/realtime-js` directly as external dependencies, re-exporting them through thin wrappers that apply supython URL and header defaults. This means upstream improvements (new PostgREST features, realtime protocol updates) arrive through dependency bumps without SDK code changes.

## 15. Known Limitations (v0.1.0)

- **Auto-refresh on 401** covers PostgREST requests only. Storage and Functions callers must handle 401 retries manually.
- **Auth methods** are limited to email+password. OTP, magic link, OAuth, and password recovery endpoints exist on the server but are not yet wrapped.
- **Storage `list()`** — object listing is not yet available (server endpoint pending).
- **Batch `remove()`** — only single-object removal is supported.
- **`getSession()` `expires_in`** returns `0` because the real expiry lives in the JWT `exp` claim (JWT claim parsing is deferred to a future version).
- **Realtime `postgres_changes`** — the infrastructure exists (via `@supabase/realtime-js`) but has not been tested end-to-end with the supython realtime server.
- **Cross-tab session sync** — no `window.addEventListener('storage', ...)` listener (deferred to v0.2.0).

## 16. Full Usage Example

```typescript
import { createClient } from '@supython/sdk';
import type { Database } from './types';

const supython = createClient<Database>('http://localhost:8000', {
  anonKey: 'eyJhbGciOi...',
});

// ── Auth ─────────────────────────────────────────────────
const { data: signIn, error: signInErr } =
  await supython.auth.signInWithPassword('user@example.com', 'secret');
if (signInErr) throw new Error(signInErr.message);

supython.auth.onAuthStateChange((event, session) => {
  console.log(`Auth event: ${event}`, session?.user?.email);
});

// ── PostgREST ────────────────────────────────────────────
const { data: todos } = await supython
  .from('todos')
  .select('id, title, completed')
  .eq('user_id', signIn!.user!.id)
  .order('created_at', { ascending: false });

const { data: inserted } = await supython
  .from('todos')
  .insert({ title: 'Learn supython' })
  .select()
  .single();

// ── RPC ──────────────────────────────────────────────────
const { data: count } = await supython.rpc<number>('todo_count');

// ── Storage ──────────────────────────────────────────────
const { data: bucket } = await supython.storage.createBucket('files', { public: true });
const avatars = supython.storage.from('avatars');

const file = new File(['image bytes'], 'avatar.png', { type: 'image/png' });
await avatars.upload('profile/avatar.png', file);

const url = avatars.getPublicUrl('profile/avatar.png');
const { data: blob } = await avatars.download('profile/avatar.png');

const { data: signed } = await avatars.createSignedUrl('private/doc.pdf', {
  expiresIn: 3600,
});

await avatars.remove('profile/avatar.png');
await supython.storage.deleteBucket('files');

// ── Functions ────────────────────────────────────────────
const { data: greeting } = await supython.functions.invoke<{ msg: string }>(
  'hello',
  { body: { name: 'supython' } },
);

// ── Realtime ─────────────────────────────────────────────
const channel = supython.channel('room:general');
channel
  .on('broadcast', { event: 'chat' }, (payload) => {
    console.log(payload);
  })
  .subscribe();

// Later:
supython.removeChannel(channel);

// ── Sign out ─────────────────────────────────────────────
await supython.auth.signOut();
```
